; Malformed config: group-member keys that (1) precede their opener and
; (2) overflow their group. Exercises the QUIRKS #9 fix AND pins the
; ACCEPTED overflow-rebind residual (QUIRKS #21) in FlySight/config.c.
;
; PART A -- member BEFORE opener (the -1 bug, FIXED in B7):
;   The three keys just below the header (Alarm_Type, Win_Bottom, Sp_Dec)
;   are group MEMBERS with no preceding opener, so num_alarms / num_windows
;   / num_speech are all still 0. The old parser wrote index num_x-1 == -1
;   (out of bounds). The fix requires num_x > 0, so a leading member is
;   IGNORED with no effect.
;
; PART B -- member of an OVERFLOW opener (in-bounds rebind, ACCEPTED
; residual, NOT fixed):
;   MAX_WINDOWS is 2. Two well-formed silence windows are defined below,
;   then a THIRD Win_Top. The opener's < MAX guard drops the 3rd window
;   (num_windows stays 2), but the Win_Bottom that follows it still writes
;   windows[num_windows-1] == windows[1] -- rebinding the LAST VALID
;   window's bottom (1000 m) to the overflow value (600 m). This is
;   in-bounds (not the -1 bug) but a wrong value; a numeric guard cannot
;   distinguish it from a legitimately full group (both have num==MAX).
;
; Pins in the trace:
;   1. The three leading strays are ignored -- no phantom / index -1 alarm.
;   2. The well-formed alarm (Alarm_Elev 1500 / Alarm_Type 1) fires once,
;      descending through 1500 m.
;   3. The overflow Win_Bottom 600 rebinds window 2 to [600, 1200]: the
;      vertical-speed tone is SUPPRESSED all the way down to ~600 m, not
;      just to 1000 m. Tone beeps are therefore ABSENT in the 600..1000 m
;      band (they would be PRESENT there if the overflow member had been
;      ignored) and RESUME only below ~600 m. That silence is the pin.
